# No comments

Use the caller's files or complete scoped diff. Otherwise resolve the actual base branch and include ongoing staged, unstaged, and relevant untracked changes. Read [`../poteto-mode/references/pi-runtime.md`](../poteto-mode/references/pi-runtime.md).

1. With authorized delegation, run a fresh native `comment-sicko` with the scope packet and a run-bound output. It reports proposed changes and never edits files. As part of another workflow, put this review in that workflow. Without delegation authority, inspect directly and state that fresh comment review was unperformed.
2. Read nearby code and check every proposed deletion and `MUST KILL` target. Preserve legal/license headers, public API contracts, external platform or protocol constraints, justified formatter directives, and issue/RFC links that explain a constraint code cannot express. An unproven claim is not grounds to delete a possible contract. Reject invented symbols, scope escapes, or reasons unsupported by the cited code.
3. For disputed rationale, use **how** or **why** on the scoped symbol. Audit lint and TypeScript suppressions by the actual rule. A suppression hiding a correctness defect is a root-cause finding; a style-only or faulty rule may justify keeping it.
4. Delete accepted redundant comments directly. Fix trivial accepted code findings only inside the user's implementation scope. If a fix needs a new shape, use **architect** for the sketch before implementing. A root cause outside scope stays an explicit finding.
5. Encode an important constraint as a type, test, runtime boundary, or lint when that change is authorized and useful. Keep the comment until the encoding actually protects the constraint. Do not add a new approval pause when the existing task already authorizes the reversible fix.
6. Report deletions, preserved constraints, accepted and rejected findings, encodings, verification, and open work. A missing or failed required reviewer is a review gap, never a clean independent verdict.
